## 4 · Decisions and why

| Decision | Why |
|---|---|
| Use the module numbers `00`–`15` exactly as requested, with labs, exercises and interview prep as modules 13–15 | One predictable layout; folders sort in study order |
| Number lessons `level.lesson` (3.4) and labs after their level (Lab 3.4) | You can tell where any file belongs from its name |
| Keep 8.6, 10.1 and Lab 10.1 in their original layout | Their outputs were tested on Docker Desktop on the Mac and can't be re-run in the Linux lab environment; rewriting them without re-testing would risk inventing output. They're flagged at the top of each file and listed under remaining work |
| Write new Level 3 lessons for NAT (3.8) and troubleshooting (3.11) instead of moving the old notes there | The old notes are Linux- and Docker-specific depth; beginners need the vendor-neutral idea first |
| Build labs on Linux network namespaces in one privileged container | Free, local, reproducible, safe to break, and the same building blocks Docker and Kubernetes use |
| Keep and extend the "(tested)" convention, adding "(tested on the Mac, Oct 2026)" and "(illustrative)" | Readers can always tell real output from a sketch |
| Put exercise solutions in `14-practice-exercises/solutions/` | Answers can't be seen by accident |
| Write Levels 4–12 as detailed outlines rather than thin lessons | Levels 1–3 in full depth first, as agreed; an outline that says "planned" is more honest than a shallow lesson |
| Remove `01-basics.md` only after every fact was found in its new place | No original content lost; history stays in git |
| Keep diagram file names unchanged | Other notes and `tools/diagrams_networking.py` reference them |
| **draw.io diagrams only, no Mermaid** (15 Oct 2026) | Suraj learns best from diagrams and asked for draw.io everywhere. `.drawio.svg` files render on GitHub and stay editable in draw.io; the generator code lives in `diagrams/src/` inside this folder |
| **Diagram first, much less text** (15 Oct 2026) | Same request. Lessons lead with a diagram and key-point bullets; intros, analogies, "why it matters" and summaries were cut or turned into diagrams. Every command, tested output, number, interview answer and check-yourself item was kept, so lessons shrank to about 55–70% of their lines rather than half |
| Keep ```` ```bash ```` blocks byte-identical during the rewrite | The 14 Oct lab validation stays valid: the scripts that were run are exactly the ones in the files |

## 8 · Assumptions and limitations

- **Audience:** a DevOps or cloud engineer preparing for interviews, as the original notes were; hence Path A as the main path, and Docker, Kubernetes and AWS as the main real-world examples. A network-engineering audience is served by Path B, but vendor CLIs (Cisco, Juniper) are deliberately out of scope.
- **Time estimates** are the author's estimates, not measurements of learners.
- **Tested outputs** come from one environment each (the lab container on 14 Oct 2026; the Mac on 7–8 Oct 2026). Kernel, tool and Docker versions change details such as error wording; the lessons say so where it's known to vary (for example curl 8's wording for a refused connection).
- **Vendor facts** (AWS reserved addresses, NAT gateway billing, Kubernetes default ports) were correct for October 2026 and will drift; each is marked as vendor-specific.
